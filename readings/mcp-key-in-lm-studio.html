Where a remote MCP server's key actually lives in LM Studio

One page. Read in a minute. Checked against LM Studio's own docs, 19 and 20 Nov 2026.

Short answer: in mcp.json, as a plain text line inside the server's headers block. Not in a settings screen, not in the model config, not in an env field.

{
  "mcpServers": {
    "your-remote-server": {
      "url": "https://example.com/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN_HERE"
      }
    }
  }
}

That is the shape LM Studio documents for a remote server. It follows Cursor's mcp.json notation, so if you have seen Cursor examples, it is the same idea. The token sits in headers, spelled Authorization, with Bearer and a space before the token.

Getting to that file

  • Requires LM Studio 0.3.17 (b10) or later. Earlier versions are not an MCP host at all.
  • In the app, open the Program tab in the right sidebar.
  • Click Install, then Edit mcp.json. The in-app editor opens the file.
  • Paste the server block inside mcpServers, save, and the server appears in the app.

Three ways this bites

  • Wrong block. A local server example uses command, args and env. A remote server uses url and headers. Copying the local shape and dropping a key in env does nothing for a remote URL.
  • Wrong header. The name is Authorization, and the value is Bearer <TOKEN>. Some servers use a different header name; check that server's own docs rather than assuming.
  • It is plain text on your disk. Not a keychain entry. Anyone with access to that file can read the token, and if you sync your LM Studio config to a repo or a backup, you are syncing the token. Treat that file like a password file.

The step the docs bury in a footnote

Straight from the docs page, and easy to skim past: when you add a server by hand, paste only what sits between "mcpServers": { and its closing }. Pasting the whole thing in leaves you with a mcpServers block inside mcpServers, the server never loads, and nothing tells you why. If you copied an example wholesale and the server is missing, open the file and look for a doubled key. That is the first place to look before you touch the header line.

Two cautions the same page gives, worth repeating

  • Do not install from a source you cannot read. An MCP server can run code, touch your local files, and use your connection.
  • Some servers were built for Claude, ChatGPT or Gemini and will eat your context. On a local model that shows up as a sudden overflow or a model that stops mid-answer, long before any error.

What to do when tools do not show up

Check the header line first, character by character, before you touch anything else. A mangled Bearer (missing space, extra quote) fails quietly. Then check the server block's shape: url plus headers for remote, command plus args for local. Only after both of those is it worth suspecting the server.
