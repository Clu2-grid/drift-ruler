You installed SillyTavern. Where your chats live, and what "moving them" actually means.

A chat program keeps your conversations somewhere. On a hosted service that somewhere is a company's server and you cannot see it. On SillyTavern it is a folder on your own computer, and you can open it and copy it. That is the whole difference, and it decides everything else on this page.

01Where the chats are

SillyTavern is a program that runs on your computer and opens in your browser. Your settings and your conversations are not stored inside the program. They sit in one separate folder, and since version 1.12.0 the makers moved them there on purpose, in their words, to make the data "portable and independent from the web server itself."

By default that folder is called data and it sits inside the SillyTavern folder you cloned. You can move it somewhere else, for example C:\Users\You\Documents\ST-Data, by setting dataRoot in the program's config.yaml file, or by starting it with --dataRoot and a path. Their guide asks for a full path, not a shortcut like ~.

The one thing to do first

Find that folder now, before you have anything in it. Open it once. If you know where it is while it is empty, you will not have to hunt for it on the day something goes wrong.

02Backing it up is a copy, not a feature

There is no account to sign into and no server holding a second copy. The folder is the original. Copying the folder somewhere else (another drive, a USB stick, a cloud folder) is your backup, and it is the only one you have.

Their own update guide says the same thing in its own way: it creates an automatic backup in a backups folder when it changes where things are stored, and it still tells you that a full manual copy first "is always a good practice." I would not rely on a program's update to be the day you first think about a backup.

03Two exports, and only one of them comes back

In the chat file list (the "Manage chat files" dialog) each chat has an export button. Read this before you use it, because the two formats are not equal:

  • .jsonl is the one that comes back. Their docs: it "can then be re-imported as is," with all its information. Images and attachments are left out, so those are the thing to copy separately.
  • .txt is for reading, not for moving. It is a plain text dump and, again from the docs, it "can't be re-imported again as it loses important metadata."

If you ever export a chat to keep it safe, export the .jsonl one. A text file looks friendlier and is the one that quietly ruins a move.

04Moving chats in from somewhere else

This is the part most people do not expect: bringing conversations in is actually well supported here. Their docs list imports from TavernAI, Text Generation WebUI, Agnai, KoboldAI Lite and RisuAI, and from Character.AI through a browser extension called CAI Tools.

That matters for one reason. A program that can read other programs' chat files, and write files they can read back, has made moving a format question instead of a permission question. One exception: the Character.AI route runs through a third-party browser extension rather than a file, so it is the shakiest of the list. I walk it step by step below, including where it fails.

→Worked example: out of Character.AI, step by step

This is the one path I could trace end to end at both ends, so it is the one I show. SillyTavern's own docs name it: "To import Character.AI chats and bots, use the CAI Tools browser extension." The extension's own guide, read the same day, gives the steps below. If you want to know what a paid answer looks like, this is the shape: named tools, real menu labels, and the places it breaks said out loud.

  1. Install CAI Tools from the Chrome Web Store or the Firefox add-on page. It shows up as a button on character.ai. It is a third-party extension, not something either company ships.
  2. Open the exact chat you want to keep on character.ai. The tool works on the chat you are looking at, not on your account in the abstract.
  3. Use "Download Chat" from the extension menu. In its own words: the plain download is an .html file for reading; "If you have Tavern or Silly Tavern, use that button instead." Take the SillyTavern option.
  4. For the whole history, use "Download History", press "Start fetch", and wait. Their guide says it fetches old-system chats too, and that it can take time.
  5. Characters come separately. "Download Character" gives you a character card (a PNG with the data inside) or a bare .json if there is no avatar. Both import into SillyTavern.
  6. In SillyTavern, open the chat file manager and import the file the extension produced. SillyTavern's own docs say its .jsonl form "can then be re-imported as is", so that is the shape to insist on. Character cards go in through character management.
Where this path breaks, from the tool's own changelog
  • It intercepts the site's traffic, and their notes say the interception sometimes does not start fast enough; that is their explanation for memory features failing and for imports that land as broken "shell" messages.
  • character.ai has changed its API addresses before, and their notes record a version where downloads stopped working until the extension was updated. An out-of-date extension looks like a broken chat.
  • There is a paid tier with a free trial, so some buttons may be locked when you first open it.
  • Their "Import Chat" button copies a chat into character.ai. It is not the way out. Getting out is the download step.

And where it stops: there is no equivalent extension for Google's AI Mode, because there is nothing documented to import into. Takeout hands you files, and that is where the published path ends. A person who only ever used AI Mode is not missing a step. There is no step.

05Why this is different from the company-hosted ones

If you used a hosted companion, the shape of leaving it looks like this: you ask for your data, they give you a file, and there is no documented way to load that file into a different host. Google's help pages describe its Takeout export as files (chats, and the rest) with no matching import on the other side. An agent memory host I read in November describes its memory folder as belonging to the agent, and documents no transfer between accounts.

So the pattern is not that one company is unkind. It is that files leave and nothing goes back in. A hosted service has no reason to make its exit door also work as an entrance elsewhere.

What is different here is boring and useful: the chats are ordinary files, the file format round-trips, and the program reads several other formats. That is all "portable" ever meant.

06What it costs you

You hold the chats, so you hold the backups. There is no support line that restores last month. If your disk dies and you never copied the folder, the conversations are gone, and no one can help you get them back.

The trade in one line

Hosted: someone else keeps it running and you cannot take it with you. Here: you can take it with you, and you are the one who keeps it running.

If you are going to keep a conversation you care about for months, set a reminder once a month to copy that folder. It takes a minute, and it is the only maintenance this arrangement asks of you.
